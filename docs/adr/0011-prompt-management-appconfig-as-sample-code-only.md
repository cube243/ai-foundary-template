# ADR-0011: Prompt Management/AppConfigをテンプレートでなくサンプルコード止まりにする

## ステータス
承認済み

## コンテキスト
Bedrock Prompt ManagementやAppConfigを使ったプロンプトの動的管理・段階的ロールアウトは、ADR-0010で扱ったオンラインA/Bテストの構成要素の1つでもあるが、それ以外にも「プロンプトをコードのデプロイと切り離して更新したい」という単独のニーズでも使われうる。同様にBedrock Advanced Prompt Optimizationの実行そのものも、プロジェクトごとにどう組み込むかが分かれる性質のものである。

## 決定
Prompt Management/AppConfigの構成、およびBedrock Advanced Prompt Optimizationの実行そのものは、本テンプレート群には含めず、サンプルコードとして別途提供するに留める。

## 検討した代替案
- **標準的なプロンプト管理の仕組みとして各エージェントテンプレートに組み込む**: プロンプトをどう構造化し、どのタイミングでどう切り替えるか(即時反映か、段階的ロールアウトか、承認フローを挟むか等)は、チームの開発文化やガバナンス要件に強く依存する判断であり、Terraformテンプレートとして一律に決め打ちすることは、かえって利用者の選択肢を狭めると判断した。ADR-0010のオンラインA/Bテストと同じ理由づけである。
- **Prompt Optimizationを各テンプレートのCI/CDパイプラインに組み込む**: 実行タイミングや採用基準(最適化結果を自動採用するか、人間のレビューを挟むか)がチームによって異なり、これもテンプレート側で固定化すべき性質のものではないと判断した。

## 結果・トレードオフ
得られるもの: テンプレートが「開発文化に関する意思決定」を代わりに行ってしまうことを避けられ、利用者は自分たちのやり方でプロンプト管理を組み込める。
引き換えに受け入れるもの: プロンプト管理の仕組みが必要な利用者は、サンプルコードを出発点に自分たちで構築する追加作業が発生する。テンプレートをapplyしただけでは動くプロンプト管理基盤は手に入らない。

# ADR-0001: テンプレートフォルダの完全独立性を優先し、共通コードの重複を受け入れる

## ステータス
承認済み

## コンテキスト
このリポジトリはcookiecutterで1フォルダずつ配布するIaCテンプレート集であり、利用者は`templates/*`のうち1フォルダだけを単独でコピーしてくる。認証(Cognito)・監視(構造化ログ)・テナント分離といった関心事は`templates/rag-vector-db-bedrock-kb`と将来追加される他のテンプレート(`templates/single-agent`, `templates/tool-agent`, 将来の`templates/rag-vector-db-opensearch`等)の間でほぼ同じ形で繰り返し必要になる。一時期、これらの共通コードを`_shared/`のようなディレクトリに集約し、同期スクリプトで各テンプレートに複製する「vendoring方式」を検討した。

## 決定
各`templates/*`フォルダは、他のどの`templates/*`フォルダも参照・importしてはならない。共通の関心事であっても、各フォルダに実装を重複させて自己完結させる。`_shared/`+同期スクリプトのvendoring方式も採用しない。テンプレート内部での共通化(例: `rag-vector-db-bedrock-kb/lambda_common/`)は許容するが、これはテンプレートの境界を越えない。

## 検討した代替案
- **`_shared/`ディレクトリ+同期スクリプトによるvendoring**: 一時期検討したが、これは「テンプレートフォルダ間の依存」を心配していたための過剰な対応であり、実際には各テンプレートが完全に独立していれば良いだけと判明した。同期スクリプトの保守自体が新たな負債になる。
- **共通Terraformモジュール/共通Pythonパッケージとして外部公開**: 利用者が1フォルダだけをコピーしてくるという配布モデルと相容れない。モジュール参照は「他のtemplatesフォルダへの依存」と同種の問題を生む。

## 結果・トレードオフ
得られるもの: 利用者は1フォルダをコピーするだけで、他に何も参照せず`terraform apply`できる。あるテンプレートの変更が意図せず他のテンプレートに影響することがない。
引き換えに受け入れるもの: 認証ヘルパーや構造化ログのようなコードが複数のテンプレートに重複して存在し続ける。将来的にバグ修正や仕様変更が必要になった場合、該当する全テンプレートに個別に反映する必要がある。これは意図的な設計判断であり、後から「共通化」する必要はない。
